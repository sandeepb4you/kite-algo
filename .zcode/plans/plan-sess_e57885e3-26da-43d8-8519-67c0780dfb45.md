# Go Algo Options Trading Platform — v1 Build Plan

A modular, paper-first options trading platform on Zerodha Kite. Built with clear interfaces so paper/live brokers, storage, and strategies are all pluggable.

## Tech Stack & Dependencies
- **Go 1.26** (already installed), stdlib-heavy
- `github.com/gorilla/websocket` — Kite Ticker WebSocket
- `modernc.org/sqlite` — **pure-Go** SQLite (no CGO — important for Windows, no C compiler needed)
- `gopkg.in/yaml.v3` — config
- `github.com/google/uuid` — order IDs
- stdlib for the rest (`log/slog`, `net/http`, `encoding/json`, `math`)

## Key Design Decisions

**1. Broker interface** — the central abstraction. Both `LiveBroker` (real Kite orders) and `PaperBroker` (simulated fills against live ticks) implement it. Strategies code to the interface, so switching paper↔live is a config change.

**2. Strategy interface** — pluggable: `OnTick(tick)`, `OnFill(fill)`, `Init()`, `Stop()`. The Engine fans ticks out to all registered strategies. The example ships a **Delta-based short straddle** (sell ATM CE + PE, manage by Delta threshold).

**3. Live trading is gated twice**: a `mode: live` config flag **AND** a manual startup confirmation (type `I UNDERSTAND`). Defaults to paper/dry-run. Can't go live by accident.

**4. Dry-run mode (no API keys yet)**: Kite client uses stub auth; the platform compiles, boots, logs "no credentials — running in dry-run", and can replay recorded ticks. You drop in real keys via `config.yaml` later and it just works.

**5. Windows-friendly**: pure-Go SQLite (`modernc.org/sqlite`), no CGO, no C toolchain required.

## Implementation Phases (I'll build in this order)

**Phase 1 — Foundation**
- `go.mod`, project skeleton, config loader (YAML + env), slog logger, SQLite storage + schema (orders, fills, positions, candles, optional ticks), Storage interface.

**Phase 2 — Kite Integration**
- REST client (auth/token refresh, instrument master CSV download+parse, orders, portfolio/margins), rate limiter (token bucket), WebSocket ticker with auto-reconnect + resubscribe + heartbeat, dry-run stubs.

**Phase 3 — Options Math**
- Black-Scholes Greeks (Indian options are European → BS is correct), implied volatility (bisection + Newton-Raphson), instrument symbol parsing (NIFTY24AUG24500CE → underlying/expiry/strike/type).

**Phase 4 — Trading Core**
- Broker interface + `LiveBroker` + `PaperBroker`, Risk manager (max daily loss, max positions, max order value — runs before every order), Trading Engine (wires ticker → strategies → risk → broker → storage).

**Phase 5 — Strategy Framework + Example**
- Strategy interface, example short-straddle strategy with Delta-based entry/exit, engine integration.

**Phase 6 — Main + Safety + Docs**
- `main.go` entry point, live-trading double gate (config + manual confirm), `config.example.yaml`, `README.md` with setup/run instructions.

## What you'll have at the end of v1
- ✅ A platform that boots in dry-run mode (no keys), connects & streams live ticks when you add keys, computes live Greeks, runs a pluggable strategy, paper-trades by default, and persists everything to SQLite.
- ❌ Deliberately out of scope for v1 (future work): backtesting UI, web dashboard, multi-account, futures strategies, broker other than Kite.

## A note on safety
Options can wipe capital fast. v1 is **paper-trading by default** and live requires double confirmation. Even after going live, start with **1 lot of NIFTY** to validate end-to-end before scaling.
